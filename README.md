# jennifer-view-kb-sso

## 인증키 발급 API 설정하기

 1. 관리 > 어댑터 및 실험실 > 실험실 탭 클릭
 2. 추가 버튼을 누르고, 종류는 API를 선택
 3. ID는 kb_plugin로 설정
 4. 경로에 파일선택을 해서 업로드 하지 말고, 절대 경로를 입력해야 함 (dist/kb-sso_jennifer-3.0.0.jar)
 5. 테이블에 설정이 추가되면, 해당 설정 로우를 선택하고, 옵션을 클릭

### 인증키 발급 API 사용하기

 1. 관리 > 인증 토큰 관리 > 추가 버튼 클릭
 2. 종류를 Plugin API를 선택하고, 저장 버튼 클릭
 3. http://${제니퍼5_호스트}/plugin/kbapi/authkey?user_id=${KB_사용자_아이디}&device_id=${KB_디바이스_아이디}&token=${제니퍼_인증_토큰}
 4. 제니퍼 인증 토큰은 [설정 > 인증 토큰 관리 > 추가 > Plugin API]로 생성할 수 있음
 5. 같은 사용자와 디바이스의 키가 메모리에 남아 있으면 기존 키를 반환하고, 최초 발급부터 10초가 지나 만료되면 새 키를 생성함

v2와 같이 API가 `KbLoginAdapter.AUTH_KEYS`에 인증키를 저장하고 로그인 어댑터가 같은 메모리를 조회·비교한다. 조회나 인증 성공으로 유효시간을 연장하거나 키를 즉시 삭제하지 않는다. 만료는 최초 발급부터 경과한 10초이며, 시스템 시각 조정의 영향을 받지 않는다. 여러 요청이 동시에 와도 유효한 캐시 키 하나를 반환한다.

새 키는 `user_id`, `device_id`, 발급 시각(밀리초), 순번, 보안 난수를 입력으로 HMAC-SHA256을 계산한 43자 문자열이다. 영문 대소문자·숫자·`-`·`_`만 사용하며 `/`, `+`, `=`, `%`, 공백은 포함하지 않는다. HMAC 비밀키는 서버에서 자동 생성하며 추가 설정은 필요 없다. 캐시 인덱스도 사용자와 디바이스의 경계를 구분해 다른 조합이 같은 캐시 항목을 사용하지 않도록 한다.


## 로그인 어댑터 설정하기

 1. 관리 > 어댑터 및 실험실 > 로그인 탭 클릭
 2. 추가 버튼을 누르고, 종류는 SSO를 선택
 3. ID는 kb_login로 설정
 4. 경로에 파일선택을 해서 업로드 하지 말고, 절대 경로를 입력해야 함 (dist/kb-sso_jennifer-3.0.0.jar)
 5. 클래스 란에는 com.aries.kb.login.KbLoginAdapter를 입력
 6. 테이블에 설정이 추가되면, 해당 설정 로우를 선택하고, 옵션을 클릭
 7. 사용자 아이디는 인증키 발급 API 호출시 user_id 매개변수의 값인 ${KB_사용자_아이디}로 지정됨
 8. KB_JENNIFER_PASSWORD 옵션 추가 (기본값은 guest, 위와 동일)

### URL로 제니퍼 로그인하기

 1. 일단 인증키 발급 API를 호출하여, 인증키를 발급 받는다.
 2. http://${제니퍼5_호스트}/login/sso?user_id=${KB_사용자_아이디}&device_id=${KB_디바이스_아이디}&auth_key=${플러그인_생성_인증키}를 호출해야 한다. (제한시간 10초)

로그아웃 후 다시 로그인할 때도 인증키 발급 API를 호출한다. 최초 발급부터 10초 안에는 같은 키로 검증할 수 있고, 만료 후 호출하면 새 키를 반환한다. 10초는 마지막 조회나 API 응답 수신 시점이 아닌 최초 발급 시점부터 계산한다. 응답의 `X-KB-SSO-Remaining-Millis`는 남은 유효시간을 나타낸다.

로그인은 GET `/login/sso` 요청으로 처리한다. 서블릿이 쿼리 문자열을 한 번 디코딩한 다음, v2 형식의 응답을 호출 측에서 다시 인코딩해 남은 `%2F`, `%2B`, `%3D`가 있으면 한 번 더 정규화한다. 이미 디코딩된 `+`는 공백으로 바꾸지 않는다. 잘못된 퍼센트 인코딩은 인증 실패로 처리한다.

발급 API URL의 `token`은 제니퍼의 Plugin API 호출 자격 증명이다. 10초 만료 후 갱신되는 값은 API 응답으로 받는 `auth_key`이다.

### 새 버전 적용 확인

API 실험실의 `kb_plugin`과 로그인 어댑터의 `kb_login`에서 사용하는 JAR를 모두 최신 `kb-sso_jennifer-3.0.0.jar`로 교체하고 같은 절대 경로로 등록한 뒤 뷰서버를 재시작한다. 기존에 발급한 키는 재시작 후 사용할 수 없으므로 API를 다시 호출한다. v2와 동일하게 발급과 로그인은 같은 뷰서버·클래스로더의 `KbLoginAdapter.AUTH_KEYS`를 사용해야 한다.

새 버전의 발급 API 응답에는 다음 헤더가 포함된다.

- `X-KB-SSO-Version: 3.0.0`
- `X-KB-SSO-Build: v2-memory-1`
- `X-KB-SSO-Issuance-Id`: 캐시 사용 여부와 무관하게 호출마다 생성되는 응답 추적 ID
- `X-KB-SSO-Remaining-Millis`: 캐시 키의 남은 유효시간
- `Cache-Control: no-store`, `Pragma: no-cache`

로그에는 키·사용자·디바이스 원문 대신 SHA-256의 일부인 추적 태그를 남긴다. `token`과 비밀번호도 출력하지 않는다.

- `AUTH_RUNTIME`: API/로그인 역할, 빌드, 프로세스, 저장소 ID, 클래스 로더와 실제 JAR 경로. API와 로그인 로그의 `process`와 `store`가 다르면 같은 메모리를 조회하지 않는 상태다.
- `AUTH_KEY_ISSUED` / `AUTH_KEY_REUSED`: 새 발급 또는 캐시 반환, 키 추적 태그, 남은 시간.
- `AUTH_CHECK` / `AUTH_KEY_NORMALIZED`: 로그인 어댑터 진입, 인코딩 정규화 여부.
- `NOT_EXIST_HEADERS`: 필수 매개변수 누락.
- `NOT_EXIST_KEY`: 해당 저장소에 키가 없거나 만료됨.
- `INVALID_KEY`: 키 불일치, 잘못된 인코딩·길이 등 구체적인 `reason`.
- `LOGIN key_verified=true jennifer_auth=pending`: 키 비교 성공 후 제니퍼로 `UserData` 반환. 이 로그 이후의 실패는 제니퍼 계정·비밀번호·호스트 처리 로그를 확인한다.

`KbSsoFlowTests`는 GET API 응답을 실제 로그인 쿼리 문자열로 넘겨 `KbLoginAdapter.preHandle()`과 반환값을 검증한다. 반복 검증·로그아웃/재로그인, 실제 10초 만료, 퍼센트 및 이중 인코딩, `/ + =`가 있는 v2 캐시, 실패 로그를 검사한다. `KbSsoHttpTests`는 로컬 서블릿 컨테이너에 실제 HTTP GET 요청을 보내 공백·한글·특수문자 및 이중 인코딩까지 검증한다. 이 테스트들은 제니퍼 서버의 계정 인증이나 운영 클래스 로더를 대신 실행하지는 않는다.

## 빌드하기

JDK 17 환경에서 다음 명령을 실행한다.

```shell
mvn clean test package -Pjennifer
```

빌드된 플러그인은 `dist/kb-sso_jennifer-3.0.0.jar`에 생성된다.
